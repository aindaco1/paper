# Paper 1.0.2 validation

Target: Paper 1.0.2 (12), arm64, macOS 13+. This patch keeps the published 1.0.1 Platform/support pins and Sparkle 2.10.0.

## Mission Control behavior

Paper explicitly orders its overlays out while a full-display Dock overview is visible, and reuses them on exit. Retaining stationary windows avoids the delayed restoration observed with transient panels. The monitor checks current public on-screen window metadata every 50 ms while an overlay is eligible; cached Dock window IDs were rejected because repeat entry can use a different window. Existing off, sleep/session and pause/exclusion rules remain authoritative.

No screenshot capture, event tap, display adjustment, new permission or rendering dependency is added. Accessibility and System Events are used only by the native test fixtures, never by the product.

The user confirmed readable top-row previews and responsive entry and exit during development. Metadata checks alone do not establish thumbnail pixel contents. The development build passed 11 repeated-Mission-Control/off/exclusion checks, six fullscreen checks and 23 display/panel checks. Short process sampling showed approximately 0.02% of one CPU core while active and 20 interrupt wakeups/second; the overview monitor stops while off. This excludes WindowServer/display costs and is not a battery-life result.

## Source and distribution gates

The combined source passed 91 Paper XCTest cases, seven Platform desktop cases, two shared-support cases, four relay contracts, two native-oracle tests, exact-pin/vendor validation and the tracked-secret scan. Developer ID build-and-launch verification passed from a temporary checkout outside iCloud, avoiding generated-bundle Finder metadata that can break code signing.

Final signed-app native results, exact executable hashes, app/DMG notarization and staples, mounted-installer checks, source-ZIP rebuild, exact-main CI, public checksums/feed and the actual previous-version updater acceptance are recorded in the delivered `Paper-1.0.2-*.json` evidence and release entry. These are separate gates required by the [release workflow](../releasing.md).

## Qualification limits

Testing uses the current M1 Max/macOS 27 host. Other macOS versions and physical display hardware, login startup, Stage Manager, audible VoiceOver, whole-device battery discharge and provider-specific authorization/capture remain on the [roadmap](../roadmap.md). Historical sleep/wake or HDR results are not re-certified by this patch.
