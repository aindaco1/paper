# Paper 1.0.3 validation

Target: Paper 1.0.3 (13), arm64, macOS 13+. Platform/support pins and Sparkle 2.10.0 are unchanged.

## Dock and Command-Tab behavior

The previous detector treated a full-display Dock layer-20 window as Mission Control. Dock reveal and Command-Tab also use that surface. The corrected PaperCore policy identifies the separate overview owner/layer while the narrow AppKit adapter continues reading current public window metadata. No window titles, screen capture, input hooks or new product permissions are involved.

The [source investigation](dock-command-tab.md) records reproduction in the old app, six new Swift regressions, two new oracle tests and 67 passing real-app checks. These cover both interactions twice, manual off, display exclusions, repeated overview entry/exit, fullscreen, geometry and floating panels. The full Swift suite has 97 tests.

## Release acceptance

The release workflow requires source/contract/Swift checks, exact-main CI, a fresh source-ZIP build, Developer ID signing, notarized/stapled app and DMG, mounted-installer equivalence, signed Sparkle archive/feed, public-download verification and a real 1.0.2-to-1.0.3 update. Final outcomes and executable hashes are recorded in the local `Paper-1.0.3-*.json` evidence and release entry; source tests alone do not establish those outcomes.

The signed artifact must repeat the native Dock/Command-Tab and Mission Control checks. Metadata does not inspect thumbnail pixels. Other supported macOS versions, physical displays and the remaining [qualification matrix](../roadmap.md) are not certified by this patch.
