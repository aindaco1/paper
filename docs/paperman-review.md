# Paperman comparison — September 25, 2026

Reviewed Paperman's current [site](https://paperman.cc/), [3.12.0 changelog](https://paperman.cc/changelog), and linked help articles against Paper's source. These are vendor-described capabilities, not a hands-on audit of Paperman. Its homepage mixes older texture descriptions with newer announcements; the changelog and specific help articles are the stronger references.

Paper covers the central use case: generated textures, intensity/grain, click-through overlays, monitor selection, app inclusion/exclusion, snooze, battery rules, fixed/solar schedules, login startup and signed updates. It also has saved looks, imports, library backup, native Shortcuts and reviewed diagnostics. Paper's inclusion and exclusion lists are already separate. A larger texture count does not establish visual equivalence.

| Gap or comparison | Paper assessment | Decision |
| --- | --- | --- |
| Single-instance behavior, described in Paperman 3.4.4 | Normal reopening uses Launch Services, but there is no product-level guard against two app copies. The build script only stops known development copies. | High priority: activate the existing process and prevent stacked overlays and competing shortcuts. Reuse a proven native adapter. |
| Protected system UI | Paperman documents overlay interference with [App Store authorization](https://paperman.cc/help/app-store-purchases-blocked) and [Apple Pay Touch ID](https://paperman.cc/help/apple-pay-touch-id). Paper orders windows out when paused, but those system workflows are not qualified. | High priority acceptance: verify off, snooze and app exclusion really remove coverage; document the supported pause path. Never bypass system protections or initiate a purchase for testing. |
| Screenshot/recording behavior | Paperman advertises exclusion and later window-screenshot fixes. Paper explicitly requires pausing and makes no capture-invisibility promise. | High priority compatibility matrix for system screenshots, window selection, sharing and common recorders. Investigate only public, permission-free approaches; retain explicit pause where exclusion is unreliable. No event taps, screen capture or universal hiding claims. |
| System light/dark appearance | Paperman's [texture help](https://paperman.cc/help/choose-a-texture) describes appearance-linked selections and per-texture intensity. Paper's automatic looks use solar times and a city. | Useful next feature: add system appearance as an alternative trigger for the existing two saved looks. Preserve manual off and app/display rules. |
| Customizable global keys | Paperman's [hotkey help](https://paperman.cc/help/keyboard-shortcuts) documents configurable actions for toggle, snooze, textures and intensity. Paper offers a fixed toggle plus native Shortcuts actions. | Useful next feature: editable toggle with conflict feedback first; optional snooze/next-favorite bindings through the same command layer. No event taps or duplicate settings surfaces. |
| Texture-specific intensity, battery percentage threshold, quick favorite switching | Paperman advertises these conveniences; Paper already offers saved looks, battery/Low Power rules and favorites in the picker. | Lower priority; validate demand before adding more persistent state or controls. |
| Desk Lamp, transition effects and sound | Paperman advertises ambient lighting and animations. They do not close a core texture-overlay gap. | Optional exploration only. Keep the static, low-energy renderer as the default; do not copy proprietary artwork or names. |

The most important gaps are operational reliability and capture/protected-UI compatibility, followed by appearance-aware looks and configurable keys. No new feature above is implemented by this review. Other Apple Silicon models, older supported macOS versions, external HDR panels/docks and whole-device battery measurements remain qualification work, not established compatibility.

## 0.5.0 follow-through

The local build implements the four identified product priorities and the approved smaller enhancements: instance ownership, system appearance, configurable shortcuts, texture-intensity recall, battery threshold, favorites in the menu and static ambient lighting. Pausing now closes/discards overlay windows. Provider-specific authorization/capture acceptance remains distinct from this implementation.

Four further workflows were not described in the reviewed [app-exceptions help](https://paperman.cc/help/app-exceptions) or [public changelog](https://paperman.cc/changelog): app-specific saved looks, connected-display desk profiles, a shortcut-adjustable clear reading strip, and persistent presentation pause. The user approved all four for this build. This is a public-document comparison, not proof of absence from unpublished Paperman builds.
